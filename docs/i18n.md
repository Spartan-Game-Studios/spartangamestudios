# Translations

The site ships in **English, Spanish, French, and German**, via
[i18next](https://www.i18next.com/) + `react-i18next`.

> [!IMPORTANT]
> The non-English copy is **machine-assisted and has not had a native-speaker
> pass**. It is good enough to develop and demo against; it should be reviewed
> by a human before the site is announced publicly, especially the devlog
> essay and the marketing taglines, where tone matters more than accuracy.

## The one rule

**Anything that lives in `src/data/` keeps its English inline as the source of
truth, and locale files override it by key. Anything hardcoded in a component
lives in the locale files outright.**

That split is what keeps "adding a game is a one-array edit" true. You write
the English in `games.ts` and it renders in every language immediately;
translators add `catalogue.<slug>.*` at their own pace, and any key they have
not reached falls back to English rather than rendering blank or leaking a raw
key onto the page.

| Kind of text                                    | Lives in                   | Overridden by          |
| ----------------------------------------------- | -------------------------- | ---------------------- |
| Nav, buttons, labels, page copy                 | `src/i18n/locales/en.json` | the other locale files |
| Game tagline / pitch / genre / features / price | `src/data/games.ts`        | `catalogue.<slug>.*`   |
| Devlog title / summary / body                   | `src/data/devlog.ts`       | `posts.<slug>.*`       |
| Studio tagline & description                    | `src/data/studio.ts`       | `studio.*`             |
| Ownership pledge                                | `src/data/studio.ts`       | `pledge.points.<id>.*` |

Never translated: the studio name, game titles, platform names (`Windows`,
`Steam Deck`), and storefront brand names.

## Files

```
src/i18n/
  index.ts          i18next init — bundled resources, detection, fallback
  locales.ts        the locale registry (codes, endonyms, resolution)
  content.ts        useGameCopy / usePostCopy / useStudioCopy / usePledgeCopy
  useHtmlLang.ts    keeps <html lang> in step with the active locale
  locales/*.json    the bundles
```

## Adding a locale

1. Add the code and its endonym to `LOCALES` in `src/i18n/locales.ts`.
2. Copy `locales/en.json` to `locales/<code>.json` and translate it.
3. Register it in `resources` in `src/i18n/index.ts`.
4. Run `pnpm test` — the parity suite tells you exactly which keys are missing,
   which placeholders you dropped, and which arrays changed length.

Content keys (`catalogue.*`, `posts.*`) are optional; add them as translations
land. Everything else must be complete.

## What the tests enforce

`src/i18n/i18n.test.ts` runs against every locale and fails on:

- a chrome key present in English but missing from a locale (and vice versa)
- a dropped or renamed `{{placeholder}}`
- a missing `<mail>` tag in the one string that uses `<Trans>`
- a blank string anywhere
- a `catalogue.*` / `posts.*` entry naming a game or post that does not exist
- a translated `features` list or devlog `body` whose length no longer matches
  the English (a dropped bullet or paragraph)

`src/routes.test.tsx` additionally renders **every route in every locale** and
fails if any dotted translation key leaks into the rendered text.

## Detection and persistence

Order: `?lang=xx` querystring → `localStorage` (`sgs-locale`) → browser
`navigator` language → English.

`load: 'languageOnly'` means `es-419`, `es-ES`, and `es-MX` all resolve to the
`es` bundle instead of missing.

The picker (footer) writes the choice to both i18next and `?lang=`, so a
localised URL is shareable. English drops the parameter.

## Known limitation: SEO

Language is a client-side preference, not part of the URL path. Every locale of
a page therefore shares one canonical URL, with `?lang=` `hreflang` alternates
emitted into `<head>` and into `sitemap.xml`.

That is enough for a crawler to discover the other languages, but it is **not
enough for the non-English pages to rank independently**. If that ever matters,
the fix is locale-prefixed routes (`/es/games/lantern`) plus prerendering —
a routing change, not a translation change. None of the copy would move.

## Rich text

Strings with a link or emphasis mid-sentence use `<Trans>` with named
components, not string concatenation — word order differs per language, so the
tag has to be inside the translated string:

```json
"permissionKeys": "Review keys and preview builds: <mail>{{email}}</mail>. …"
```

```tsx
<Trans
  i18nKey="press.permissionKeys"
  values={{ email: studio.pressEmail }}
  components={{ mail: <a href={`mailto:${studio.pressEmail}`} /> }}
/>
```

## Dates

`formatDate(iso, locale)` runs through `Intl`, so month order and casing come
free (`6. August 2026`, `6 de agosto de 2026`). Dates are parsed and formatted
in UTC so a post never slips a day across time zones.
